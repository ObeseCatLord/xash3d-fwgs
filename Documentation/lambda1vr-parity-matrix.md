# Lambda1VR oracle-to-desktop parity matrix

**Source traceability verdict: PASS for the inspected worktree. Runtime parity
verdict: INCOMPLETE.** Every required Team Beef/Lambda1VR user-visible behavior
family has a stable desktop source mapping. This does not promote startup,
build, packet, or map-load evidence into gameplay acceptance.

Evidence codes: **S** source inspected; **U** executed unit/automated check;
**Sim-start** simulated OpenXR startup/render checkpoints only; **Sim-net**
simulated two-client network checkpoint; **P** physical headset/controller;
**W** Windows build/runtime. A dash means no evidence is recorded. Simulated
results below come from `xash3d-fwgs/Documentation/openxr-completeness-audit.md`.

## Scope and exclusions

| In scope | Explicitly excluded |
| --- | --- |
| Windows and Linux OpenXR; base Half-Life, Blue Shift, Opposing Force, standalone They Hunger, and SevenKewp/Sven plus the They Hunger conversion. | Android JNI/VrApi, Android surface/performance/refresh code, and remote IK. Remote IK has no Team Beef/Lambda1VR oracle behavior to port. |

Behavioral oracle code under the Android host tree is cited only for portable
input/render semantics. Android-only internals in
`Lambda1VR/Projects/Android/jni/src/Lambda1VR/TBXR_Common.c` and
`Lambda1VR/Projects/Android/jni/src/Lambda1VR/L1VR_SurfaceView.c` remain outside
the product boundary.

## Search closure and runtime boundary

Repository-wide `rg` over all five client/server trees found definitions and
call sites for `VR_Reset`, `VR_UpdateCurrentWeapon`, `VR_UpdateViewmodel`,
`UpdateVRPose`, `UpdateVRPoseSidecar`, the three sidecar callbacks, `updatevr`,
and `vruse2`. Renderer-wide search found both presentation cvars consumed in
`xash3d-fwgs/ref/gl/gl_studio.c`. No required user-visible behavior family is
currently unmapped, so there is no source-traceability FAIL row to report.

The simulated record proves OpenXR/session/UI startup for base and Sven,
representative Sven map startup, all 58 TH conversion map
startups, and a modern mixed VR/non-VR two-client checkpoint. It does **not**
prove locomotion, gestures, scopes, two-hand use, melee, weapon handling,
save/load, physical controllers/haptics, expansion campaigns, or Windows.
